# Задачи и дежурства — локальная версия 2

Версия развивается локально в `assets/tasks/` и `src/Task/`; сервер REKLAM Hub не менялся. Предпросмотр: `http://127.0.0.1:8043/tasks` с демонстрационной базой в `preview/tasks-preview-data.json` (файл игнорируется Git). До внедрения нужно пройти обычное ревью и развёртывание через репозиторий.

## Дежурства

- Дежурство теперь имеет отдельное повторяющееся расписание: название, цвет, комментарий, активность, семь дней недели, общее время или время по каждому дню, несколько сотрудников на день, шаблоны задач.
- Назначение сотрудника работает перетаскиванием; доступен и вариант «нажать на человека → нажать на день». Все времена расписания — Europe/Moscow. Если конец раньше начала, смена продолжается до следующего дня.
- Каждый сотрудник получает **собственную** смену и копию шаблонных задач. Это позволяет однозначно считать личные результаты. Изменение шаблона действует со следующего дня и не переписывает прошедшие смены.
- Прошлые смены находятся в отдельной приглушённой секции; при открытии видны исполнитель, время, доля выполненных задач и сами задачи. Нажатие на задачу открывает её карточку.
- Смены создаются автоматически при первом обращении к модулю в этот день. Дополнительно подготовлена команда `app:tasks:materialize-duties` для запуска по расписанию, чтобы задачи появлялись и без входа сотрудника. Её запуск в production нужно согласовать с тимлидом.

## Задачи и просрочки

- Компактные карточки используют один стиль на рабочем столе и в истории смен. Задача открывается поверх страницы; справа — чат с сообщениями и ссылками на результат. Файлы напрямую пока не прикрепляются.
- Просрочка касается только обычных, ещё не завершённых задач. Такая карточка краснеет и переносится в отдельную колонку. В карточке нужно указать причину и новый срок; сервер не разрешает менять срок, ответственного или статус через обычное редактирование до фиксации просрочки.
- Каждый перенос — отдельная запись с автором, причиной, прежним и новым сроком. Личный кабинет показывает текущие просроченные задачи и историю причин за выбранный период. Позднейшее выполнение не стирает историю переноса.
- Дедлайн выбирается в адаптированном календаре бухгалтерии: один день, время, быстрый выбор «Сегодня», «Завтра», «Через неделю». Он используется в карточке, при создании, в рабочей таблице и при переносе просрочки.
- Поле «Поставил» редактируемо автором записи или администратором задач. Фактический создатель записи хранится отдельно и показывается, если он отличается от выбранного постановщика. Существующие задачи получают постановщика из прежнего поля автора миграцией.
- У одной задачи может быть несколько ответственных. Она видна каждому назначенному сотруднику, обсуждение и статус у неё общие: закрытие одним человеком закрывает задачу для всех. Для личной статистики запоминается состав ответственных на момент закрытия. Прежний единственный ответственный автоматически переносится в новый список.

## Рабочий стол и обратная связь

- Ниже задач показаны два блока: график закрытых задач по дням за 7 дней с зелёной линией выполненных и красной линией невыполненных и открытый рейтинг команды за 30 дней. Каждая горизонтальная линия графика равна одной задаче; дополнительная таблица под ним убрана. Рейтинг содержит только имя, число выполненных задач и баллы, но не чужие задачи.
- Для статистики сохраняются время закрытия и сотрудник, которому зачтён результат. Повторное открытие задачи очищает текущий факт закрытия. Миграция заполняет эти поля для уже закрытых задач по последнему времени изменения; для старых записей это приближение, а не точная историческая дата.
- «В срок» — доля закрытых задач с дедлайном, которые выполнены до него без переноса; «с переносом» — доля закрытых задач с дедлайном и хотя бы одним запросом нового срока. При отсутствии базы для расчёта показывается «—».
- Справа на рабочем столе виден блок комментариев руководителя; сотрудник может свернуть его стрелкой вправо и раскрыть обратно. Выбор запоминается в этом браузере отдельно для каждого сотрудника. Создание и удаление комментария доступны только при `TASK_ADMIN_ACCESS` (удаление требует подтверждения в интерфейсе); сотрудник видит только адресованные ему комментарии. Руководитель видит историю в разделе «Администрирование».

## Администрирование и статистика

- В форме комментария руководитель ищет сотрудника по имени. Раздел «Статистика» показывает итоги по команде и сравнительную таблицу; можно оставить в выборке нескольких сотрудников или открыть задачи и причины переносов одного человека.
- Период выбирается тем же календарём, что и в бухгалтерии: быстрые интервалы или произвольные даты. По умолчанию открыты последние 30 дней. Время и границы дней считаются по Москве.
- В общих списках видны закрытые как «не выполнены» задачи, ещё открытые задачи с прошедшим дедлайном и история переносов с причиной, прежним и новым сроком. Списки показывают ответственного; задача открывается нажатием.
- У новых переносов сохраняется сотрудник, назначенный в момент переноса. Миграция заполняет это поле для прежних переносов по автору записи, а если автора нет — по нынешнему ответственному. Для таких старых записей исторический ответственный может быть неточным.
- «Поставлено» считает задачи, созданные в периоде и назначенные сотруднику сейчас. «Выполнено/не выполнено» считает завершённые в периоде задачи по сотруднику, которому зачтён результат. «В срок» считает закрытые до дедлайна без переносов. «Просрочено сейчас» показывает открытые задачи, дедлайн которых уже прошёл и попал в период. Эти определения также подписаны в интерфейсе.
- В блоке «Все задачи» руководитель видит задачи всех сотрудников, может искать, фильтровать, открывать общую карточку, менять её поля и писать в обсуждении.
- Отдельный блок «Журнал аудита» раскрывается по нажатию. Он показывает новые создания и изменения задач, переносы дедлайнов и сообщения с автором и временем. Изменённые поля показываются как «было → стало»; историю до установки миграции восстановить нельзя. Записи загружаются порциями по 100.
- Общая статистика считает каждую общую задачу один раз, а в строке каждого ответственного она учитывается отдельно. При переносе дедлайна сохраняется список всех ответственных на тот момент.

## Проверка и развёртывание

Локально проверить `npm run typecheck:tasks`, `npx vite build --outDir preview/tasks-build`, затем открыть страницу на 8043. PHP и PostgreSQL в этом Windows-окружении отсутствуют, поэтому PHP-синтаксис, Doctrine mapping, миграции и интеграционные сценарии **ещё не проверены**.

Перед внедрением с тимлидом: синхронизировать код с актуальной веткой GitHub; проверить все миграции на staging (`Version20260920100000`–`Version20260920160000`); проверить права `TASK_ACCESS` и `TASK_ADMIN_ACCESS`; настроить ежедневный запуск команды в 00:05 МСК; протестировать работу нескольких сотрудников, общие задачи, ночные смены и просрочку. Данные существующей бухгалтерии в локальный предпросмотр не копируются.

Не включены в эту версию: автоматическая передача незакрытых заявок следующему дежурному, настоящие вложения в чат и интеграции с CRM/бухгалтерией. Их правила нужно согласовать отдельно до включения в работу.
