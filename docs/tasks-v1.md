# Задачи и дежурства — первая локальная версия

Актуальные изменения расписаний и просрочек описаны в `docs/tasks-v2.md`.

Модуль встроен в существующую оболочку REKLAM Hub. Исходники интерфейса — `assets/tasks/`, страницы `/tasks`, `/tasks/table`, `/tasks/duties`, `/tasks/profile`. Данные хранятся в PostgreSQL через API `/api/v1/tasks`. Локальный просмотр использует **ту же собранную версию интерфейса**, но подменяет API демонстрационными данными.

## Реализовано

- Личный рабочий стол: свои активные и завершённые задачи, создание и редактирование задачи, цвет, срок, приоритет, ответственный, статус, результат.
- Обсуждение задачи с автором и временем сообщения. В обсуждение можно вставить ссылку на результат или подтверждение; загрузки файлов пока нет.
- Рабочая таблица с поиском, фильтром статуса и редактированием основных полей прямо в строке.
- Дежурства: просмотр расписания; для руководителя — создание и изменение смен. Пункты чек-листа при создании становятся задачами дежурного. При изменении можно добавить пункты, но нельзя незаметно удалить уже созданные задачи.
- Активное дежурство закреплено снизу личного рабочего стола. Его незавершённые задачи подсвечиваются фиолетовым.
- Базовые личные показатели за 7, 30 или 90 дней.
- Отдельное право `TASK_ADMIN_ACCESS` в матрице ролей. Для его использования у роли также должен быть включён доступ «Задачи» (`TASK_ACCESS`).

## Локальный просмотр

В каталоге проекта:

```powershell
npm install
npm run typecheck:tasks
npx vite build --outDir preview/tasks-build
node preview/tasks-preview.mjs
```

Открыть `http://127.0.0.1:8043/tasks`. Демоданные сохраняются в игнорируемом Git файле `preview/tasks-preview-data.json`. Продакшен-данные локальный просмотр не запрашивает.

## Установка позднее, вместе с тимлидом

1. Сверить эту ветку с актуальной веткой сервера/репозитория и оформить обычный pull request. Не переносить модуль на сервер отдельным патчем поверх рабочей копии.
2. Проверить PHP/Doctrine и фронтенд в окружении проекта: маршруты, маппинг сущностей, миграцию `Version20260920100000`, сборку Vite и интеграционные тесты.
3. Сохранить резервную копию базы. Только после ревью применить миграцию на staging, проверить роли и сценарии, затем повторить через штатный процесс в production.
4. Существующие бухгалтерские данные не затрагиваются этой миграцией. Демооперации локального просмотра на сервер не отправляются.

## Следующий этап

Ещё не реализованы автоматическая передача незавершённых задач следующему дежурному, интеграции с CRM/бухгалтерией, загрузка файлов, общий рейтинг и отчёты руководителя. Для них нужно отдельно согласовать правила передачи/сроков и видимость персональных результатов. Серверную PHP-часть необходимо проверить в окружении с PHP и БД до развертывания.
