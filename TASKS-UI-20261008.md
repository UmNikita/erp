# Tasks UI correction package — approved for deployment

User approved Git publication and production deployment on 2026-10-08. Local preview:
http://127.0.0.1:8043/tasks (demonstration data only).

## Changes

- Global module links use full navigation; Tasks and Accounting also recreate their Vue roots on Turbo cache restores and body replacement. This addresses the empty-root navigation failure mode. The exact production failure has not been independently reproduced.
- Tasks secondary navigation matches the corporate sidebar style.
- Manager feedback is a separate full-height right sidebar on the desktop, with collapse control. Comments scroll independently and team ranking is pinned at the bottom. On narrow screens the panel follows the workspace. Feedback remains recipient-private. Personal results span the entire main content width.
- “Личная история” replaces the module-specific profile; no profile avatar.
- A large upper workspace board switches between personal and multi-assignee tasks. All employees share the same five statuses and column layout. Only administrators can edit names, colors and order. Individual funnels and adding/deleting statuses are intentionally deferred.
- Native drag-and-drop moves tasks through the existing API; the existing task details dialog also supports status changes. Card-level status selectors and repeated status labels have been removed from the board. Overdue regular tasks still require a reason and new deadline first.
- The board is a white panel matching the statistics cards. Column height is responsive to the viewport but does not depend on task count; every task list scrolls independently with a fixed column header. The outer board scrolls horizontally only when all columns do not fit.
- Table filters include multiple employees with checkboxes, all/me shortcuts, search, status, priority, source, deadline and requester. Filtering cannot widen server-side visibility.

## Access policy update

- Ordinary Tasks access is inherited from CRM_ACCESS by the central voter. Explicit legacy TASK_ACCESS grants are retained. CRM_ACCESS does not grant TASK_ADMIN_ACCESS.
- Root administrators and users explicitly granted TASK_ADMIN_ACCESS (with module access) administer the funnel, duty schedules, feedback, all-task view, team statistics and audit.
- Ordinary employees keep their workspace, table, personal history, own duty shifts and task-specific conversations. Existing task ownership/visibility rules remain unchanged.
- Administrative schedule definitions are no longer included in employee bootstrap data. Private feedback remains recipient-filtered.
- Direct HTML requests to administration and duty configuration require TASK_ADMIN_ACCESS. The Vue route outlet also refuses to mount those views for non-admins. API administrative checks remain enforced independently.
- The role settings table explains that CRM automatically grants ordinary tasks access.
- Validation: 75 module API/page assertions pass for CRM-only employee, delegated task administrator, root, legacy task-only employee and denied user. PHP/container/Twig/ORM checks, PHPUnit (6 assertions), Tasks type check and frontend regression tests pass.
- The first direct-page test exposed missing ignored frontend vendor assets in the isolated test checkout. Existing vendor assets were copied there read-only from the live checkout; validation then passed. Production users, role assignments and code were not modified.

## Ranking page and unread feedback

- Team ranking is pinned to the bottom of the right sidebar, separate from the comment scroll area. The scoring paragraph is replaced by a small blue link to /tasks/ranking; that page displays the full ranking table and scoring explanation. It is available to ordinary module users and reveals aggregates only.
- Feedback is sorted newest first, with ID descending as a timestamp tie-breaker.
- Collapsed feedback panel turns red when unread comments arrive. Own feedback refreshes every 30 seconds while the document is visible and when focus/visibility returns.
- IntersectionObserver marks a comment read only when it becomes visible in the expanded panel. Read state is stored server-side, remains stable on repeated read requests and survives reloads. Only the recipient can mark their feedback read, including for administrator accounts.
- Version20261008180000 adds nullable read_at; existing comments are unread until viewed.
- Verification: 89 integration assertions and PHPUnit 6 assertions pass in the disposable database. Browser confirms incoming red state, newest comment at top, clearing after viewing, ranking flush with sidebar bottom and the separate ranking link.

## Release procedure

scripts/deploy-tasks-git.sh deploys the Git delta from 8a01dc0 only. It first compares affected production source files with the previous release, refuses unexpected overlaps, preserves live configuration and unrelated CRM changes, saves private source/database backups and supports restoring source on failure. Database changes are additive; rollback retains the new table and nullable read column. Old hashed frontend assets are retained for cached clients.
